## Objective

Build a deterministic, secret-safe narrative layer that converts typed operational events and decision-related records into plain English operator summaries without modifying Gatekeeper schemas, execution behavior, live-trading authorization, or persistence semantics.

## Inputs

- `OperationalEventRecord` objects from the WI-56 operational event ledger.
- `OperationalEventType`, `OperationalEventSeverity`, `OperationalEventSource`, and `OperationalEventReasonCode` enum values.
- Bounded `OperationalEventPayload` fields such as dry-run status, provider name, budget remaining, market count, readiness state, and aggregate decision action.
- Repository-backed operational event windows returned by `OperationalEventRepository.read_window()`.
- Existing `LLMEvaluationResponse` schema for verifying no presentation fields are added.
- Existing secret/high-cardinality validation patterns in `src/schemas/ops.py`.
- Phase 16 PRD requirements for future WI-58, WI-59, and WI-60 consumers.

## Outputs

- `src/observability/operational_narratives.py`.
- Presentation schemas in `src/schemas/ops.py`, such as `OperationalNarrative`, `DecisionNarrative`, `RuntimeNarrative`, and `NarrativeRenderResult`.
- Typed render status and failure/reason enums for narrative success, fallback, redaction, and validation failure paths.
- Deterministic event/reason mapping for budget blocks, cooldown blocks, provider failures, market rejection/quarantine, readiness changes, decisions, dry-run execution, circuit breaker transitions, alerts, recovery events, and generic unknown mappings.
- Secret-safe rendering helpers that reject or redact forbidden narrative output before returning it.
- Optional repository-backed read/render helper that uses `OperationalEventRepository` without adding write or mutation behavior.
- `tests/unit/test_WI-57-deterministic-human-narratives.py`.
- `tests/integration/test_WI-57-deterministic-human-narratives.py`.

## Acceptance Criteria

1. Narrative schemas exist separately from `LLMEvaluationResponse`.
2. `LLMEvaluationResponse` has no `human_summary`, `operator_summary`, narrative, presentation, dashboard-only, or digest-only fields.
3. Runtime narrative rendering does not call Claude, DeepSeek, Grok, or any other LLM.
4. Supported event types and reason codes render deterministic English summaries.
5. The same input event renders identical output across repeated runs.
6. Narratives explain what happened.
7. Narratives explain why it happened using stable typed reason codes.
8. Narratives explain whether the bot continued, skipped, degraded, or stopped when that state is inferable from the event.
9. Narratives include operator inspection hints when applicable.
10. Budget block narratives cover daily, hourly, token, cost, and reflection budget reasons.
11. Cooldown block narratives cover repeated hold and repeated invalid-response reasons.
12. Provider failure narratives cover failed provider calls and malformed provider responses.
13. Market rejection and quarantine narratives cover ineligible, not found, cooldown, and quarantined reasons.
14. Readiness change narratives cover ready, degraded, and not-ready reasons.
15. Decision narratives cover accepted BUY/HOLD/SKIP-style aggregate actions and typed skip reasons.
16. Dry-run execution narratives state that no live signing or broadcasting occurred.
17. Circuit breaker narratives cover opened, closed, and override reason codes.
18. Alert narratives cover dispatched and dispatch-failed outcomes without Telegram identifiers or tokens.
19. Recovery narratives cover handled and unhandled error categories without raw exception text.
20. Unknown but valid event/reason combinations return conservative generic summaries.
21. Malformed payload JSON returns a typed render failure or safe fallback summary and does not crash.
22. Narrative output never includes raw prompts, private reasoning, raw provider responses, API keys, wallet keys, Telegram tokens, token IDs, condition IDs, wallet addresses, raw exception messages, or high-cardinality identifiers.
23. Narrative output is scanned for forbidden content before it is returned to callers.
24. Narrative rendering does not mutate operational events or expose repository update/delete methods.
25. Any repository helper added for narratives is read-only and routes through `OperationalEventRepository`.
26. No raw database session is held by agent or observability presentation code for event reads beyond repository boundaries.
27. Metrics/log labels from narrative rendering remain low-cardinality.
28. No live trading, signing, broadcasting, or `DRY_RUN=false` behavior is added or changed.
29. No trading calculation, sizing calculation, or Gatekeeper decision is performed by the narrative layer.
30. All Decimal-bearing narrative inputs remain Decimal-safe at schema boundaries.
31. Targeted WI-57 unit and integration tests pass.
32. Full regression remains compatible with the documented baseline and coverage stays at or above 80%.
33. MAAP is run before commit for any change touching `src/schemas/`, `src/db/`, `src/observability/`, `src/orchestrator.py`, `src/agents/`, or other core logic.

## Anti-Patterns

- Do not enable live trading.
- Do not change `DRY_RUN=false` behavior.
- Do not add live signing or broadcasting.
- Do not bypass `LLMEvaluationResponse`.
- Do not add `human_summary`, `operator_summary`, or any presentation field to `LLMEvaluationResponse`.
- Do not use Claude, DeepSeek, Grok, or any LLM to generate runtime narratives.
- Do not derive narrative text from raw prompts, raw reasoning, raw provider responses, raw exception messages, token IDs, condition IDs, wallet addresses, or secrets.
- Do not expose high-cardinality identifiers in narrative text, logs, tests, metrics labels, dashboard-ready structures, or future replay/digest inputs.
- Do not write operational events from the narrative layer.
- Do not add update or delete behavior to `OperationalEventRepository`.
- Do not call `Base.metadata.create_all()` in runtime paths.
- Do not add new database tables or migrations for this WI unless implementation proves they are strictly necessary and is approved first.
- Do not implement the incident replay CLI, dashboard activity feed, or daily operations digest in this WI.
- Do not introduce new external package dependencies.
- Do not use raw `float` for money, spend, EV, Kelly, PnL, price, sizing, exposure, or token-cost values.
- Do not allow narrative rendering failures to crash WebSocket, evaluation, execution, or shutdown loops.
